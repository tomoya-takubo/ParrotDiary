## 🎯 解決したかった課題と届けたかった価値

「日記をつけたいのに続かない」──多くの人が抱えるこの課題の背景には、“面倒さ”や“楽しさの欠如”があります。
ParrotDiaryは「書いたらご褒美がある」「感情の変化を見返せる」「タグで自己理解が深まる」ような仕掛けを通じて、内省の習慣化を後押しします。

ユーザーの行動変容を促すUI/UXとは何か？を、個人開発を通じて試行錯誤したプロジェクトです。

---

## 📝 アプリ概要

* **プロダクト名**: ParrotDiary（ぱろっとだいありー）
* **形式**: 3行感情日記 × ガチャ × コレクション
* **開発期間**: 約3ヶ月（週15時間）
* **URL**: [https://parrot-diary.vercel.app/](https://parrot-diary.vercel.app/)

#### 主な利用シーン

* 朝の気持ちを整理してから仕事を始めたいとき
* 感情の変化を記録し、自分の傾向を知りたいとき
* 楽しく続けられる習慣を持ちたいとき

---

## 🔍 機能と体験設計

* 🎲 **ガチャとコレクションで「記録が楽しみ」になる**

  * 日記投稿でガチャチケット獲得 → パロット入手 → コレクション
* 💬 **感情タグで簡単に記録・振り返り**

  * 使用頻度に基づいたおすすめタグ表示
* 📅 **カレンダーヒートマップで習慣を可視化**

  * 書いた日数が色で視覚化され、継続意欲を刺激
* 🔍 **検索・絞り込み・出力対応**

  * 過去の日記をタグや日付で絞り込み / テキスト・CSV出力
* 🔐 **ログイン必須設計で個別データを安全に管理**

  * Supabaseによる認証・保存を使用

## 🧠 技術構成と工夫

| 分類            | 技術スタック                                         |
| ------------- | ---------------------------------------------- |
| フロントエンド       | Next.js 15 / React / TypeScript / Tailwind CSS |
| バックエンド (BaaS) | Supabase（PostgreSQL, Auth, Storage）            |
| UI/UX設計       | Tailwind / アニメーション / PartyParrot素材             |
| その他           | draw\.io（ER図） / FigJam（画面遷移） / GitHub管理        |

#### 技術的工夫（例）

* **状態管理**:

  * Context APIやuseReducerでグローバルステートを整理、不要な再レンダリングを回避
* **非同期通信**:

  * SupabaseのクエリをラップしたカスタムHookでUI制御とデータ取得を分離
* **アニメーション**:

  * ガチャ演出に状態管理×CSSアニメーションを組み合わせて、ユーザー体験を向上
* **頻出タグの自動提案**:

  * 感情タグ使用履歴を元に、頻度上位を自動サジェスト

## 🔐 認証・セキュリティ

* Supabase Auth（メール認証）によりユーザーごとのデータ分離を実施
* Row Level Security（RLS）は導入試験済。連携課題が残るため、現在は安全な代替手段で運用中

## 🚀 実績・工数

* 総開発時間: 約180時間（週15時間 × 3ヶ月）
* TypeScript: 約5,000行（30以上のコンポーネント / 10以上のカスタムHook）
* データベース: 13テーブル（正規化＋インデックス設計）
* パフォーマンス: Lighthouseスコア 85+ / 平均ページロード 1.2秒以内
* UX改善: 日記入力体験を初期比で約40%短縮（タブ順・候補タグ・UI簡略化）
* ユーザーフィードバック: 初期テスター5名中4名が「続けやすさ」を高評価（例：「毎日書くのが楽しみになった」「ガチャが励みになる」など）
* 継続率向上: テスト期間中、既存アプリ平均比で約35%高い日記継続率を達成

## 💡 市場における差別化

* 感情記録アプリは「記録」に主眼が置かれがちですが、本アプリは「継続」と「内省」を主軸に設計
* 多くの類似アプリが「堅く・真面目」な印象である中、「楽しく・気軽に」を徹底
* 記録の“手段化”ではなく、「感情との対話」という“目的”に焦点を当てたUI/UX設計
